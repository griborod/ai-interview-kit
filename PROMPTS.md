# Промпты для собеса

Три случая. Определи заранее, какой у тебя, — спроси рекрутера: чьё окружение,
какой инструмент, какой язык, будет ли готовый репозиторий.

`<KIT_URL>` — адрес этого репозитория после push (GitHub/GitLab, публичный —
иначе в чужом окружении нужна авторизация).

---

## Случай 1. Своё окружение (мой VS Code + Claude Code)

Накануне, в терминале:

```bash
~/scripts/ai-interview-kit/install.sh --user      # поставить скиллы набора
```

На собесе: открыть репозиторий задачи, **новый** чат. Если в репозитории нет
`AGENTS.md`, поставить шаблон: `install.sh --project .` (не попадёт в git).

---

## Случай 2. Окружение интервьюера, агент со скиллами и интернет

Сначала спросить разрешения поставить свои скиллы. Затем вставить агенту:

```text
Установи мой набор скиллов для этой сессии.
1. Склонируй <KIT_URL> во временную папку вне репозитория: /tmp/ai-interview-kit.
2. Прочитай /tmp/ai-interview-kit/install.sh и в двух строках скажи, что он сделает.
3. Запусти из корня текущего репозитория: bash /tmp/ai-interview-kit/install.sh --project .
   Скрипт ничего не перезаписывает и прячет свои файлы через .git/info/exclude.
4. Ничего не коммить. Покажи список установленных скиллов: clarify, task-spec, verify-done,
   review-diff, tdd-lite, debug-loop, parallel-agents, karpathy-coder.
5. Если инструмент подхватывает скиллы только в новой сессии — скажи, я её открою.
```

Cursor может не видеть `.claude/skills` / `.agents/skills` — тогда попросить
агента скопировать `skills/*` в `.cursor/skills/`.

---

## Случай 3. Скиллов нет (чужой инструмент, нет интернета, только чат)

Вставить в начало сессии — это весь процесс набора в одном сообщении:

```text
Работаем по такому процессу, держи его всю сессию.

1. Уточнение. Изучи репозиторий read-only (README, манифест, entrypoints, тесты, код по
   задаче) и дай карту кода в 5–8 строк. Затем топ-7 вопросов, которые я задам
   интервьюеру, таблицей «вопрос | какое решение зависит | допущение по умолчанию»;
   короткие, закрытые или «A или B?»; не спрашивай то, на что отвечает код. Категории:
   цель и пользователь, MVP/scope, входы-выходы и объём, можно ли менять код, нагрузка и
   надёжность, сбои и граничные случаи, внешние API или моки, как оценивают, приоритеты.
   После моих ответов — мини-дизайн до 15 строк: компоненты, поток данных, интерфейсы,
   ключевое решение с альтернативой, риски, порядок срезов.
2. Спека до кода. Создай TASK.md (до 40 строк): Goal, Context, Constraints, Invariants,
   Design, Acceptance criteria (проверяемые, минимум один негативный/граничный),
   Out of scope, Assumptions, Verification (точные команды). Повторно не спрашивай.
   Жди моего «ок».
3. План 3–7 шагов, первым — минимальный работающий срез.
4. Реализация: минимальный diff, только нужные файлы, без спекулятивных абстракций.
   Для логики с чёткими входами/выходами — сначала тест, убедись что он падает по
   правильной причине. Ошибка — воспроизведи, одна гипотеза, одно изменение; после трёх
   неудачных фиксов остановись и доложи.
5. Независимые части (поиск в доках, тесты под согласованный интерфейс) — предлагай
   делать параллельно и объясняй, почему.
6. Перед словом «готово»: прогони команды из Verification сейчас и покажи вывод; дай
   таблицу «критерий | статус | доказательство»; честно назови непроверенное.
7. Ревью: перечитай diff как чужой код против TASK.md. Ищи выдуманные API, проглоченные
   ошибки, тесты которые проверяют моки или подогнаны, хардкод под тестовые данные,
   граничные случаи (пусто/None, часовые пояса, float для денег), правки вне scope.
Никогда не говори «работает» без запуска в этой сессии.
```

## Старт задачи (любой случай)

Первые 2–3 минуты — сам: прочитать задачу и задать интервьюеру рамочные
вопросы (цель и для кого, что значит «готово», что оценивают). Пока говоришь —
агент изучает код:

```text
Задача: <вставить текст задачи как есть>.
Запусти clarify: изучи репозиторий read-only, дай карту кода и топ-7 вопросов
интервьюеру таблицей «вопрос | решение | допущение по умолчанию».
Ничего не меняй и не пиши код.
```

Выбрать 5–7 вопросов, задать, затем:

```text
Ответы интервьюера: <список>. Остальное — по твоим допущениям.
Набросай мини-дизайн, после моего «ок» — task-spec → TASK.md.
```

Бюджет: ~10–12 мин на уточнение и дизайн, ~10 мин в конце на проверку и ревью.

## Финиш задачи

```text
Прогони verify-done по TASK.md, затем review-diff свежим субагентом
(только TASK.md + diff + команда тестов). Проверь каждую находку сам перед
исправлением. Итог: таблица критериев и список found / fixed / rejected.
```
